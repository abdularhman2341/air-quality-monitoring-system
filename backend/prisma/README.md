# Database (Prisma)

The database schema is managed with [Prisma](https://www.prisma.io/) ORM.
Owner: Abdulmalik Alaqeel (Database Developer).

```
backend/
├── prisma/
│   ├── schema.prisma           # Tables, fields, and relations (source of truth)
│   ├── custom-constraints.sql  # Rules Prisma cannot express (added to the init migration)
│   ├── migrations/             # Generated by Prisma — commit this folder
│   ├── seed.js                 # Test user and device for development
│   └── README.md
└── src/db/prisma.js            # Shared Prisma client used by the backend
```

## Tables

| Model | Table | Purpose |
|---|---|---|
| `User` | `users` | Accounts. Passwords stored as hashes only. |
| `Device` | `devices` | One ESP32 per row, identified by its MAC. `owner_id` is null until paired. |
| `Reading` | `readings` | One row per MQTT reading message. |
| `Alert` | `alerts` | One row per alarm episode. `ended_at` is null while active. |
| `Session` | `sessions` | Sign-in sessions. Valid until `expires_at` unless `revoked_at` is set. |

## First-time setup

1. Install Prisma (from the `backend/` folder):
   ```bash
   npm install @prisma/client
   npm install --save-dev prisma
   ```
2. Add the seed command to `backend/package.json`:
   ```json
   "prisma": {
     "seed": "node prisma/seed.js"
   }
   ```
3. Set `DATABASE_URL` in `backend/.env` to a **local** PostgreSQL database (see `.env.example`).
   `prisma migrate dev` also needs permission to create a temporary "shadow" database on that server.

## Creating the first migration (done once, by the database owner)

1. Generate the migration **without applying it**:
   ```bash
   npx prisma migrate dev --create-only --name init
   ```
2. Open the new file `prisma/migrations/<timestamp>_init/migration.sql`.
3. Paste the full content of `prisma/custom-constraints.sql` at the **end** of it.
4. Apply it:
   ```bash
   npx prisma migrate dev
   ```
5. Add the test data:
   ```bash
   npx prisma db seed
   ```
6. Commit the whole `prisma/migrations/` folder.

## For other team members

After pulling changes that include a new migration:

```bash
npm install
npx prisma migrate dev     # applies new migrations to your local database
npx prisma db seed         # optional: test user and device
```

## Production (Railway)

Never run `migrate dev` against Railway. Apply committed migrations with:

```bash
npx prisma migrate deploy
```

Recommended: make it part of the start command in `package.json`, so every deploy applies new migrations first:

```json
"start": "prisma migrate deploy && node src/index.js"
```

Never run the seed on production.

## Custom constraints

These rules are enforced by the database but cannot be written in `schema.prisma`, so they live in SQL inside the init migration:

| Rule | Constraint |
|---|---|
| Email stored in lowercase | `users_email_lowercase` |
| MAC is 12 uppercase hex characters | `devices_mac_format` |
| ADC value between 0 and 4095 | `readings_adc_range` |
| Gas concentration is not negative | `readings_ppm_positive` |
| Alert ends after it starts | `alerts_end_after_start` |
| At most one open alert per device | `alerts_one_open_per_device` (partial unique index) |
| Session expires after it is created | `sessions_expiry_after_creation` (in the `add_sessions` migration) |

> **Check every future migration.** Prisma does not know about the partial index `alerts_one_open_per_device`. After running `prisma migrate dev --create-only` for a new change, open the generated `migration.sql` and delete any `DROP INDEX "alerts_one_open_per_device"` line before applying it.

## Notes for the backend

- **Emails:** lowercase before saving and before searching: `email.trim().toLowerCase()`.
- **MACs:** remove `:` and `-`, then uppercase, before saving or searching.
- **Storing readings** (ignores QoS 1 duplicates):
  ```js
  await prisma.reading.createMany({ data: [reading], skipDuplicates: true });
  ```
- **IDs are `Int`, not `BigInt`**, so they convert to JSON without extra code.
- **Decimal values are `Float`**, so they appear as numbers in JSON, not strings.
